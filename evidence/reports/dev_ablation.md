# Where the gain came from: development-set analysis

Generated by `dev_ablation.py` from the development scorecards in `scorecards/dev/` (labelled copy). Every number below is recomputed by that script, which exits non-zero if this file or the card section differs from what it computes.

## Read this first

- **Descriptive and after the fact.** This analysis was not planned before the training runs. It re-reads the development scorecards produced when the release 2.0 recipe was chosen; no model was trained or scored for it, and no test set is used. The differences describe these training runs on these sets; they are not measured causal effects.
- **The recipe variants were not built to isolate one change each.** Only adding FalseReject and adding the bag-of-words correction change one thing. Adding teacher labels also adds 100,000 prompts; adding the alarming-but-benign data adds two pools at once; the base recipe against the release 1.0 trial checkpoints changes data, starting weights and training settings at once. No comparison separates the warm start from the data.
- **Same number of steps, different passes over the data.** Every training run of the recipe variants took 9,396 optimizer steps at batch 32, so a variant with fewer rows sees each row more often: without the alarming-but-benign data 2.81 times, without FalseReject 2.21, the base recipe and the bag-of-words variant 2.00, with teacher labels 1.20. This is part of every comparison except the bag-of-words one. The release 1.0 trial checkpoints trained for up to 5 epochs on 13,132 rows at batch 16 and each kept the checkpoint with the best ToxicChat validation AUPRC, which favours them on that split.
- **The held-back rows are in-domain for the variants that train on their source.** The WildGuardMix, WildJailbreak and FalseReject held-back rows were held back from the same sources as the training pools. So adding FalseReject, and adding the alarming-but-benign data, compare on the FalseReject held-back rows a variant that trained on FalseReject with one that did not; adding the alarming-but-benign data likewise on WildJailbreak's benign held-back rows; and every variant against the release 1.0 trial checkpoints on all three (the trial checkpoints trained on none of these sources).
- **The paired prompts were generated in-house** for this project: 602 pairs of a harmful and a benign prompt on the same topic. No training run saw them, but they are not an independent public benchmark.
- **The teachers were calibrated on two development sets.** Each teacher's score was Platt-scaled (two parameters) on the labels of the ToxicChat validation split and the Aegis 2.0 validation set before it set the teacher-label variant's targets, so that variant's figures on those two sets are not fully independent of its training targets.
- **Small sets and few runs.** The ToxicChat validation split has 38 unsafe prompts, so its AUPRC is noisy. The release 1.0 trial checkpoints are two runs with the same seed (they differ only by GPU nondeterminism), not three seeds, so their run-to-run spread is understated.
- **The trial checkpoints' Aegis 2.0 validation set.** They were scored on an earlier 1,199-row version; 40 rows that match test items were removed before the other runs were scored. They are evaluated here on the 1,159 shared rows.

## Method

- Point estimates: AUROC (sklearn `roc_auc_score`) and AUPRC (`average_precision_score`) on P(unsafe); a variant's value is the mean over its training runs. A two-model average's score is the sigmoid of the two runs' mean logit margin.
- Intervals: 10,000 paired bootstrap draws. Benign and unsafe items are resampled separately within each set, with the same item draws for every training run; each set has its own stream, `numpy.random.default_rng([13, zlib.crc32(set file name)])`. Inside each draw a variant's training runs are resampled with replacement (stream `training_runs:<variant key>`). For the FalseReject held-back rows the strict threshold is recomputed in every draw from that draw's benign rows of the ToxicChat validation split and the Aegis 2.0 validation set.
- An interval is the 2.5th to 97.5th percentile of the 10,000 draws of the difference.
